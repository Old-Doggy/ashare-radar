# Tushare 限频、限速与配额（5000 积分账号）

> 本文记录本项目用到的 Tushare Pro 接口频率限制、代码里的默认节流参数，以及如何调整。
> 官方文档查阅时间：2026-11-27（[积分与频次权限对应表](https://tushare.pro/document/2?doc_id=290) 及各接口文档页）。

## 1. 官方限制（5000 积分）

| 范围 | 限制 | 说明 |
|---|---|---|
| **账号整体** | **500 次/分钟** | 常规数据每天总量无上限（2000 积分档为 200 次/分钟、单接口每天 10 万次） |
| `daily` | 500 次/分钟，单次 6000 行 | 5000 积分基础档即可 |
| `daily_basic` | 2000 积分起，5000 积分无总量限制 | 按积分表 500 次/分钟 |
| `adj_factor` | 2000 积分起，5000 以上可高频 | 按积分表 500 次/分钟 |
| `stk_limit` | 2000 积分起，分钟级流控 | 单次最多 5800 行 |
| `moneyflow` | 2000 积分起，积分越高频次越高 | 单次最多 6000 行 |
| `margin` | 2000 积分起，积分越高频次越高 | 单次最多 4000 行 |
| `index_daily` | 2000 积分起，5000 以上频次相对较高 | 按积分表 500 次/分钟 |
| `trade_cal` | 2000 积分 | 按积分表 500 次/分钟 |
| **`limit_list_d`** | **200 次/分钟 + 每天总量 1 万次** | 8000 积分以上才是 500 次/分钟、无日总量限制 —— 本项目最容易被卡住的接口 |
| **`stock_basic`** | **50 次/分钟** | 官方明确建议“拉一次后本地缓存”，本项目只在建库/刷新元数据时调用 |

> 注意：积分表里的“每分钟 500 次”是账号整体口径；个别接口（`limit_list_d`、`stock_basic`）另有更低上限，实际以**更严格的那个**为准。

## 2. 本项目的默认节流（留 20%–40% 余量）

| 参数 | 默认值 | 官方上限 | 余量 |
|---|---|---|---|
| 全局限速 | **400 次/分钟** | 500 | 20% |
| 任意两次请求最小间隔 | **0.15 s** | — | 避免瞬时突发 |
| `limit_list_d` | **160 次/分钟** | 200 | 20% |
| `stock_basic` | **40 次/分钟** | 50 | 20% |
| `limit_list_d` 日总量 | **9000 次/天** | 10000 | 10% |

实现位置：`pipeline/ratelimit.py`（滑动窗口 + 线程锁 + 最小间隔 + 日预算）。
所有 Tushare 调用（`daily/daily_basic/adj_factor/stk_limit/limit_list_d/moneyflow/margin/index_daily/trade_cal/stock_basic`）都经过同一限速器。

### 自动退避与“不封号”行为

1. **限频错误自动重试**：Tushare 返回“每分钟最多访问该接口…”等限流信息时，按指数退避重试
   （默认 2s、4s、8s、16s、32s + 随机抖动，最多 6 次），不会因为一次限频就中断建库。
2. **无权限立即跳过**：返回“没有访问该接口的权限 / 积分不足”时不重试、不重复烧请求，
   本次运行后续所有交易日都跳过该接口（如 `limit_list_d`），并在报告/日志中记录。
3. **单进程约束**：`publish_lock` 保证同一时间只有一个更新/建库进程，避免两个进程叠加把频率打满。
4. **可中断续跑**：建库按交易日写 `core_dataset_checkpoint`，中断后**重跑同一条命令会跳过已完成日**
   （只回放最后 20 个交易日），不需要从头再来。
5. **请求统计**：建库/更新结束会打印并写入报告，例如
   `[bootstrap] 完成：2400 个交易日，请求 31200 次，限速等待 812s；无权限集合=无`
   （`data/meta/bootstrap.json` / `update_*.json` 的 `rate` 字段）。

## 3. 环境变量（可选覆盖）

在 `.env` 或系统环境变量里设置（不设置即用上表默认值）：

```dotenv
# 全局限速（次/分钟）
TUSHARE_RATE_GLOBAL_PER_MIN=400
# 任意两次请求最小间隔（秒）
TUSHARE_RATE_MIN_INTERVAL=0.15
# 单接口限速（JSON，未列出的接口按全局值）
TUSHARE_RATE_LIMITS_JSON={"limit_list_d":160,"stock_basic":40}
# 单接口每日请求预算（JSON）
TUSHARE_RATE_DAILY_TOTAL_JSON={"limit_list_d":9000}
# 限频重试：最大次数与退避基数（秒）
TUSHARE_RATE_MAX_ATTEMPTS=6
TUSHARE_RATE_BASE_DELAY=2
```

如果你想更保守（例如账号还有别的脚本在跑）：把 `TUSHARE_RATE_GLOBAL_PER_MIN` 调到 200、
`TUSHARE_RATE_LIMITS_JSON` 里 `limit_list_d` 调到 80 即可，只是建库会慢一些。

## 4. 实测参考

- 全历史建库（2016-12-01 起，约 2,400 个交易日）需要按日请求 7 类数据 + 4 个指数，
  官方限频 + 网络耗时下通常 **1.5–3 小时**；本项目的节流不会成为主要瓶颈（网络耗时占大头）。
- 每日增量（`python -m pipeline.release`）只回放最近约 20 个交易日 + 当日，通常在
  **1–3 分钟**内完成。

## 5. 常见问题

- **报“每分钟最多访问该接口”**：限速器会自动退避重试；持续出现说明账号同时有其它任务在跑，
  把它们停掉或调低 `TUSHARE_RATE_GLOBAL_PER_MIN`。
- **`limit_list_d` 一直 unavailable**：该接口需要额外积分/权限；本项目会跳过并在页面把
  炸板率/封单额显示为 `—`，不影响其它指标。
- **建库中途关闭窗口**：直接重跑同一命令即可续跑；已完成的交易日会被跳过。
